# TCP — надёжный поток байтов

[Главная](../README.md) · [Раздел](README.md) · [Словарь](../00_Navigation/Glossary.md)

## Зачем нужен

Предоставляет приложениям упорядоченный поток байтов: подтверждает приём, повторяет потерянное и регулирует отправку.

## Место в сети

Транспортный уровень поверх IP. Пара портов различает приложения; единого порта TCP нет.

## Как происходит обмен

1. SYN, SYN-ACK и ACK устанавливают соединение и начальные номера последовательности.
2. Данные передаются сегментами; Sequence Number относится к байтам.
3. При пропуске части данных подтверждения указывают, какой следующий байт ожидается.
4. SACK при согласованной поддержке сообщает и о полученных диапазонах; отправитель повторяет недостающее.
5. FIN и ACK завершают передачу по направлениям; аварийный сброс возможен через RST.

## Пример

Файл должен прийти целиком и в порядке. Приложение читает поток, даже если сеть делила его на несколько сегментов.

## Что важно различать

TCP не шифрует содержимое и не сохраняет границы сообщений приложения. Flow control защищает получателя, congestion control ограничивает нагрузку на сеть.
