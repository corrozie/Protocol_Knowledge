# Reverse Proxy — вход к серверному приложению

[Главная](../README.md) · [Раздел](README.md) · [Словарь](../00_Navigation/Glossary.md)

## Зачем нужен

Принимает входящие соединения от клиентов перед группой серверов приложения. Может завершать TLS, выбирать backend и распределять нагрузку.

## Место в сети

Архитектурная роль, а не отдельный протокол. Снаружи часто HTTPS/443; внутри — HTTP или HTTPS.

## Как происходит обмен

1. DNS направляет клиента на адрес прокси.
2. Клиент устанавливает TLS с прокси.
3. При TLS offload прокси расшифровывает запрос и передаёт его backend-серверу по HTTP.
4. Backend обрабатывает запрос и отвечает прокси.
5. Прокси шифрует ответ для клиентского соединения.

## Пример

Веб-приложение доступно через один публичный адрес, за которым находятся несколько внутренних серверов.

## Что важно различать

Offload оставляет внутренний участок без TLS. Re-encryption создаёт второй TLS-канал; passthrough пропускает TLS до backend. Заголовки Forwarded/X-Forwarded-For следует доверять только от контролируемого посредника.
