# HTTPS — защищённый веб

[Главная](../README.md) · [Раздел](README.md) · [Словарь](../00_Navigation/Glossary.md)

## Зачем нужен

Передаёт HTTP через защищённое соединение: обеспечивает конфиденциальность, целостность и проверку подлинности сервера.

## Место в сети

Прикладной HTTP с TLS. В уроке TCP/443; HTTP/3 использует QUIC поверх UDP/443.

## Как происходит обмен

1. Браузер обрабатывает URL https и узнаёт IP через DNS.
2. Для сценария HTTP/1.1 или HTTP/2 устанавливается TCP-соединение.
3. TLS согласует ключи; браузер проверяет сертификат сервера и имя сайта.
4. Запросы и ответы HTTP передаются в защищённом канале.
5. Браузер отображает полученную страницу.

## Пример

Посредник в публичной сети не должен видеть пароль из HTTPS-запроса при корректной проверке сертификата и отсутствии перехвата на устройстве.

## Что важно различать

HTTPS не гарантирует добросовестность владельца сайта. IP-адрес, объём и время обмена могут оставаться наблюдаемыми; скрытие DNS требует отдельного механизма.
