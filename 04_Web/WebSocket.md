# WebSocket — двусторонний обмен

[Главная](../README.md) · [Раздел](README.md) · [Словарь](../00_Navigation/Glossary.md)

## Зачем нужен

Поддерживает длительный двусторонний канал: сервер может отправлять сообщения без отдельного HTTP-запроса для каждого события.

## Место в сети

Прикладной уровень поверх TCP; ws обычно 80, wss с TLS обычно 443. Урок показывает Upgrade из HTTP/1.1.

## Как происходит обмен

1. Клиент устанавливает TCP, а для wss также TLS.
2. HTTP-запрос предлагает Upgrade: websocket и передаёт ключ рукопожатия.
3. Сервер отвечает 101 Switching Protocols с подтверждением.
4. Стороны обмениваются кадрами данных в обоих направлениях.
5. Ping/Pong проверяют живость канала, Close согласует завершение.

## Пример

Сервер чата сразу доставляет новое сообщение браузеру, не ожидая очередного опроса страницы.

## Что важно различать

Маскирование клиентских кадров не является шифрованием. Для конфиденциальности нужен wss. WebSocket не определяет формат прикладных сообщений чата.
