# HTTP Proxy — посредник клиента

[Главная](../README.md) · [Раздел](README.md) · [Словарь](../00_Navigation/Glossary.md)

## Зачем нужен

Принимает запросы от настроенного на него клиента и обращается к серверам от его имени. Может фильтровать запросы и кэшировать ответы.

## Место в сети

Прикладной HTTP-посредник, обычно TCP; в уроке порт прокси 8080, но он настраивается.

## Как происходит обмен

1. Клиент соединяется с прокси вместо целевого сайта.
2. Для обычного HTTP передаёт в строке запроса полный URL.
3. Прокси разрешает имя и открывает собственное соединение к серверу.
4. Ответ возвращается клиенту через прокси.
5. Для HTTPS клиент просит CONNECT к host:443, после чего внутри туннеля устанавливает TLS с сайтом.

## Пример

Организация направляет веб-трафик сотрудников через общий шлюз с правилами доступа.

## Что важно различать

При обычном CONNECT прокси видит цель туннеля, но не расшифровывает HTTP внутри TLS. TLS-инспекция с доверенным корпоративным сертификатом — отдельная конфигурация.
