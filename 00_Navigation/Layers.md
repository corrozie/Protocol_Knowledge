# Уровни и инкапсуляция

[Главная](../README.md) · [Карта связей](Map.md)

## Зачем нужны уровни

Сеть решает несколько задач одновременно. Приложению нужен понятный обмен, транспорту — доставка между процессами, IP — путь между сетями, канальному уровню — передача на конкретном участке. У каждого уровня свой заголовок и своя область ответственности.

## Учебное соответствие OSI и TCP/IP

- **Прикладной уровень TCP/IP** объединяет задачи верхних уровней OSI 5–7. Здесь находятся [HTTP](../04_Web/HTTP.md), [DNS](../01_Foundations/DNS.md), [SMTP](../05_Applications/SMTP.md) и другие прикладные протоколы.
- **Транспортный уровень, OSI 4:** [TCP](../03_Transport/TCP.md) и [UDP](../03_Transport/UDP.md). [QUIC](../03_Transport/QUIC.md) предоставляет транспортные функции поверх UDP.
- **Межсетевой уровень, OSI 3:** [IP](../01_Foundations/IP.md), [IPv6](../01_Foundations/IPv6.md) и управляющие сообщения [ICMP](../01_Foundations/ICMP.md).
- **Сетевой доступ, OSI 1–2:** [Ethernet](../02_Access/Ethernet.md) и [Wi-Fi](../02_Access/WiFi.md) задают передачу на конкретном канале.

Распределение — учебная модель. [TLS](../06_Security/TLS.md) добавляет защиту между приложением и транспортом, а [BGP](../01_Foundations/BGP.md) управляет сетевой маршрутизацией, хотя его сообщения передаются через TCP. Поэтому «что делает технология» и «во что вложено её сообщение» следует рассматривать отдельно.

## Как данные вкладываются друг в друга

Для HTTPS по HTTP/1.1 примерная вложенность такая:

`HTTP-сообщение → защищённые записи TLS → поток TCP и сегменты → IP-пакеты → кадры Ethernet или Wi-Fi → сигнал`

На принимающей стороне обработка идёт в обратном направлении. Один HTTP-ответ может занимать много сегментов; границы HTTP-сообщений и TCP-сегментов не обязаны совпадать.

Для HTTP/3 цепочка иная:

`HTTP/3 → защищённые потоки QUIC → UDP → IP → канал`

TLS 1.3 участвует в согласовании ключей QUIC; это не обычные записи TLS поверх UDP.

## Адреса разных уровней

- **MAC-адрес** помогает доставить кадр по локальному каналу.
- **IP-адрес** указывает сетевой интерфейс назначения и позволяет маршрутизировать пакет.
- **Порт** TCP/UDP помогает различать приложения на узле.
- **Доменное имя** удобно человеку и приложению; DNS сопоставляет ему записи.

Пример: сервер `www.example.com`, IP `203.0.113.10`, TCP-порт `443`. Для первого локального перехода отправителю нужен MAC шлюза, а не MAC удалённого сервера. Связь адресации с реальным обменом показана в [сценарии открытия сайта](../07_Practice/Open_Website.md).
