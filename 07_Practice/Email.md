# Сквозной сценарий: отправить и прочитать письмо

[Главная](../README.md) · [Прикладные системы](../05_Applications/README.md)

1. Почтовый клиент отправителя подключается к серверу отправки по [SMTP](../05_Applications/SMTP.md). Для защищённой отправки используют, например, TLS с начала на 465 либо STARTTLS на 587.
2. После входа клиент передаёт конверт и текст письма. Адрес в конверте определяет доставку и не обязан совпадать со всеми видимыми заголовками сообщения.
3. Сервер запрашивает MX домена адресата через [DNS](../01_Foundations/DNS.md), затем узнаёт адрес выбранного почтового сервера.
4. Межсерверное SMTP-соединение, обычно на TCP/25, передаёт письмо принимающей стороне. Если доставка временно невозможна, отправляющий сервер может поставить письмо в очередь.
5. Получатель читает ящик через [IMAP](../05_Applications/IMAP.md) или [POP3](../05_Applications/POP3.md). IMAP удобен для синхронизации нескольких устройств; POP3 ориентирован на загрузку сообщений.

**Главная связь:** SMTP доставляет письмо, IMAP/POP3 открывают доступ к уже доставленным сообщениям. Наличие IMAP не заменяет SMTP для отправки.

## Границы защиты

[TLS](../06_Security/TLS.md) может защищать отдельные соединения, но между ними письмо обрабатывают почтовые серверы. Сквозное шифрование письма — дополнительный механизм и не следует автоматически из использования защищённых портов.

## Пример проверки понимания

Если письмо отправилось, но не появилось на втором устройстве, проблема может относиться к синхронизации ящика, а не к отправке. Если письмо не дошло на сервер адресата, проверяют SMTP-доставку и DNS отдельно.
