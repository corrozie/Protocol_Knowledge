# WebRTC — звонок между браузерами

[Главная](../README.md) · [Раздел](README.md) · [Словарь](../00_Navigation/Glossary.md)

## Зачем нужен

Набор технологий для передачи аудио, видео и данных в реальном времени. Сигнализация знакомит участников, ICE выбирает путь, а медиаканал защищается отдельно.

## Место в сети

Прикладной стек: SDP, ICE, STUN/TURN, DTLS-SRTP. Медиа обычно идёт по UDP; единого порта всего WebRTC нет.

## Как происходит обмен

1. Участники входят в комнату через сервер сигнализации; в уроке используется защищённый WebSocket.
2. STUN помогает узнать внешний адрес, а ICE собирает кандидатов связи.
3. Offer и Answer согласуют параметры медиа и способы связи.
4. Проверки ICE выбирают рабочую пару адресов.
5. DTLS согласует ключи для SRTP, после чего передаётся защищённое медиа.

## Пример

Два браузера могут передавать видео напрямую после знакомства через сервер. Если прямой путь не работает, может потребоваться ретранслятор TURN.

## Что важно различать

WebRTC не стандартизует конкретный протокол сигнализации приложения. Прямое соединение возможно не всегда; сервер может участвовать и в передаче медиа.
